## 为什么要全员使用 AI

- AI 已经可以参与日常工程活动
- 它不是替代人，而是降低重复劳动和信息整理成本
- 使用 AI 的差距会逐渐变成工作效率差距
- 团队需要统一方法，避免各自摸索

---

## AI 是什么

- 广义 AI：让机器完成需要人类智能参与的任务
- 当前常用的 AI：以大语言模型为核心的文本、代码、知识处理工具
- 对开发测试人员来说，AI 更像一个可对话的工作助手
- 它擅长生成、解释、归纳、改写、检查

---

## LLM 是什么

- LLM 是 Large Language Model，大语言模型
- 它通过大量文本和代码训练，学习语言和代码模式
- 它根据上下文预测和生成后续内容
- ChatGPT、公司内网模型、Copilot 背后都可能使用 LLM

**案例或场景**

把一段复杂异常日志贴给模型，请它总结可能原因和下一步排查方向。

---

## GitHub Copilot 是什么

- 面向开发场景的 AI 编程助手
- 主要集成在 IDE 中，例如 VS Code
- 可以做代码补全、解释、生成测试、辅助重构
- 更适合围绕当前代码上下文工作

**案例或场景**

打开一个 Service 方法，让 Copilot 解释输入参数、处理流程、返回值和可能异常。

---

## 公司内网模型适合什么

- 适合处理通用文本类任务
- 适合整理需求、会议纪要、方案、周报
- 适合做 Prompt 练习和知识问答
- 适合不依赖 IDE 上下文的分析工作

**案例或场景**

把一段需求说明改写成测试点清单，或者把故障经过整理成问题分析报告初稿。

---

## Agent 是什么

- Agent 是能围绕目标连续执行任务的 AI 工作方式
- 它通常包含规划、调用工具、读取文件、修改文件、验证结果
- 普通聊天是一次问答，Agent 更像持续完成一个任务
- 基础培训只需要先理解概念，不要求马上掌握

**案例或场景**

让 Agent 阅读一个小项目，定位一个报错原因，修改代码并运行测试验证。

---

## AI 能帮开发做什么

- 解释陌生代码和业务流程
- 生成样板代码、SQL、脚本
- 辅助 Debug 和日志分析
- 生成单元测试和边界条件
- 提供重构建议和代码审查线索

---

## AI 能帮测试做什么

- 根据需求生成测试点
- 根据接口说明生成测试用例
- 根据 Bug 描述补充复现步骤
- 分析日志和错误信息
- 生成测试数据和检查清单

---

## 什么任务适合交给 AI

- 输入和输出都能描述清楚的任务
- 有重复模式的任务
- 需要整理、归纳、改写的任务
- 可以由人工快速检查结果的任务
- 错了不会直接造成严重后果的草稿类任务

---

## 什么任务不适合直接交给 AI

- 目标不清楚、上下文缺失的任务
- 需要真实业务决策负责的任务
- 需要精确事实但没有可验证来源的任务
- 输出后很难人工检查的任务
- 一次性要求它完成过大任务

---

## 为什么 AI 会幻觉

- 模型会生成"看起来合理"的内容
- 它可能补全不存在的事实、接口、配置、类名
- 上下文不足时更容易编造
- 提问越模糊，结果越不稳定

**案例或场景**

让 AI 生成某个项目 API 的调用方式，如果没有提供真实代码或文档，它可能编出不存在的方法名。

---

## 工具选择速查

- 代码补全：GitHub Copilot
- 代码解释：GitHub Copilot
- 测试点整理：公司内网模型或 Copilot
- 文档总结：公司内网模型
- 日志分析：公司内网模型或 Copilot
- 小脚本生成：Copilot 优先，公司内网模型辅助

- 使用 GitHub Copilot 或公司内网模型完成一个真实工作小任务

- 有什么不足或后续想学的内容
