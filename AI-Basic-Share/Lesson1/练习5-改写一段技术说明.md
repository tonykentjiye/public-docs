# 练习 5：改写一段技术说明

---

## 练习目标

使用公司内网模型或 Copilot，将一段技术说明改写成更清晰、更易读的版本，学习 AI 在文档整理和表达优化上的应用。

---

## 练习步骤

1. 将下方原始技术说明复制到 AI 工具中
2. 使用类似以下的 Prompt 提问：
   > "以下是一段技术说明，请帮我改写成更清晰易懂的版本，要求：结构清晰、语言简洁、适合新成员阅读"
3. 阅读 AI 改写后的版本
4. 对比原文和改写版，判断是否更清晰
5. 根据你的判断进一步调整
6. 记录你的发现

---

## 练习用原始技术说明

```
系统部署说明

1. 先要装 JDK 11，配 JAVA_HOME，然后装 MySQL 5.7，创建一个数据库叫 order_system，字符集用 utf8mb4。
2. 从 Git 上把代码拉下来，分支用 release/v2.1。
3. 在 application.yml 里改数据库连接，把 url、username、password 改成自己环境的。
4. 用 Maven 打包，命令是 mvn clean package -DskipTests，打出来 jar 包在 target 目录下。
5. 把 jar 包传到服务器上，用 nohup java -jar xxx.jar > app.log 2>&1 & 启动。
6. 看 app.log 有没有报错，没报错的话访问 http://服务器IP:8080/health 看返回是不是 {"status":"UP"}。
7. 如果起不来先看日志，常见问题是数据库连不上或者端口被占用。
```

请让 AI 改写后，尝试回答以下问题：

| 问题 | 你的回答 |
|------|----------|
| AI 改写后的版本和原文比有什么改进？ | |
| 改写后的版本是否遗漏了重要信息？ | |
| 你觉得改写版本中哪些表达更好？ | |
| 如果让你再改一版，你会调整什么？ | |
| 这种改写能力可以用在哪些工作场景？ | |

## 参考：改写方向提示

一个好的改写应该关注以下几点：

- **结构清晰**：使用标题、编号、分段
- **语言简洁**：去掉冗余表达，用短句
- **步骤明确**：每个步骤只做一件事
- **补充上下文**：对新手友好的说明
- **格式规范**：代码块、加粗等 Markdown 格式
