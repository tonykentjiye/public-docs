## Markdown 是什么

- 一种轻量级文本标记格式
- 用普通文本表达标题、列表、表格、代码块
- 适合写文档、Prompt、会议纪要、说明书
- 很容易被 AI 读取和理解

---

## 常用语法：标题

```markdown
# 一级标题
## 二级标题
### 三级标题
```

- 标题用于组织结构
- 层级不要太深
- 一个标题下只讲一类内容

---

## 常用语法：列表

```markdown
- 正常场景
- 异常场景
- 边界场景
```

```markdown
1. 准备数据
2. 执行接口
3. 检查结果
```

---

## 常用语法：代码块

````markdown
```java
public void submitOrder() {
    // ...
}
```
````

- 代码块用于保留格式
- 可以标注语言
- 适合放代码、SQL、日志、配置

---

## 常用语法：表格

```markdown
| 场景 | 输入 | 期望结果 |
| --- | --- | --- |
| 正常登录 | 正确账号密码 | 登录成功 |
```

- 适合测试用例
- 适合对比方案
- 适合风险清单

## Markdown 在 AI 场景中的价值

- 让上下文更清晰
- 让 Prompt 更容易复用
- 让输出更容易转文档
- 让团队知识库更统一
- 让 AI 更容易区分章节和重点

**案例或场景**

把 Bug 信息按"现象、步骤、日志、代码、期望输出"写成 Markdown，再交给 AI 分析。

---

## AI 输入模板示例

```markdown
## 背景

这里描述业务背景。

## 问题

这里描述当前问题。

## 已知信息

- 日志：
- 代码：
- 配置：

## 希望输出

- 可能原因
- 排查步骤
- 修改建议
```

## Instruction 是什么

- 给 AI 的长期或固定行为要求
- 用来约束回答风格、输出格式、工作流程
- 可以沉淀团队规范
- 和单次 Prompt 配合使用

**案例或场景**

团队规定：代码 Review 时必须优先检查正确性、边界条件、异常处理和测试覆盖，输出按严重程度排序。

---

## Instruction 可以写什么

- 项目语言和技术栈
- 命名规范
- 测试框架
- 代码风格
- Review 关注点
- 文档输出格式
- 团队常用术语

---

## Instruction 示例：代码解释

```markdown
# 代码解释规则

当解释代码时，请按以下结构输出：

1. 一句话总结功能
2. 输入参数说明
3. 核心处理流程
4. 返回值说明
5. 可能异常和边界条件
6. 需要人工确认的问题
```

---

## Instruction 示例：测试用例

```markdown
# 测试用例生成规则

生成测试用例时，请按以下分类输出：

- 正常场景
- 异常场景
- 边界场景
- 权限场景
- 回归场景

每条用例包含：用例名称、前置条件、步骤、期望结果、优先级。
```

## 团队共享方式

- 建立统一目录存放 Prompt 和 Instruction
- 按场景分类：Bug、Review、测试、SQL、文档
- 每个模板标注适用场景和示例
- 定期清理无效或过时内容
- 优秀作业可以沉淀为团队模板

---

## 常见问题

- 写得太长，没人维护
- 写得太泛，无法执行
- 没有示例，别人不会用
- 没有版本更新，逐渐失效
- 只沉淀结果，不沉淀使用场景
