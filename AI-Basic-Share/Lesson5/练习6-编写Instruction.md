# 练习 6：编写 Instruction

---

## 练习目标

编写一份团队 Instruction，固化 AI 在特定场景下的行为要求，减少每次重复说明。

---

## 练习步骤

1. 阅读下方的 Instruction 说明和参考示例
2. 选择一个场景编写 Instruction
3. 将 Instruction 保存为 `.md` 文件
4. 用 Copilot 或公司内网模型验证效果
5. 根据验证结果调整

---

## Instruction 与 Prompt 的区别

| | Prompt | Instruction |
|--|--------|-------------|
| 作用范围 | 单次任务 | 长期有效 |
| 内容 | 具体任务描述 | 固定行为要求 |
| 更新频率 | 每次都可能改 | 稳定后少改 |
| 适用场景 | Bug 分析、生成代码 | 输出格式、命名规范、Review 标准 |

---

## 参考 Instruction 示例

```markdown
# 代码解释 Instruction

当被要求解释代码时，请始终按以下结构输出：

## 输出结构

1. **一句话总结**：用一句话说明这段代码的功能
2. **输入参数**：列出所有参数，说明类型、含义、默认值
3. **处理流程**：按步骤说明核心逻辑
4. **返回值**：说明返回值的类型和含义
5. **异常和边界**：列出可能异常和需要注意的边界条件
6. **人工确认点**：列出需要开发人员人工确认的问题

## 语言风格

- 使用简洁的中文
- 避免过度展开，每个部分不超过 3 句话
- 关键变量和函数名保留英文

## 禁止行为

- 不要直接修改代码
- 不要添加不在代码中的功能假设
```

---

## 可选场景

| 场景 | Instruction 要解决的问题 |
|------|------------------------|
| **代码解释** | 每次解释结构不一致，有的详细有的简略 |
| **测试用例生成** | 分类方式不统一，有的按功能分，有的按优先级分 |
| **代码 Review** | Review 结果格式不统一，难以对比 |
| **Bug 分析** | 分析结果缺少验证方法，无法落地 |
| **SQL 生成** | 生成的 SQL 风格和项目不一致 |
