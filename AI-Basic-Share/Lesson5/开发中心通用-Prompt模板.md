# 开发中心通用 Prompt 模板

> 适用场景：Bug 分析、代码解释、代码 Review、测试点生成、日志分析、需求分析。
> 使用方式：保留结构，按需填写；没有信息的部分可以删掉，不要留空标题。

---

## 通用模板

```markdown
# 任务名称
[例如：Bug 分析 / 代码 Review / 测试点生成 / 日志分析]

## 角色
请以[角色名称]的视角处理这个任务。
[例如：Python 开发人员 / Java 开发人员 / 测试负责人 / 代码 Reviewer / DBA]

## 背景
[描述业务背景、模块、当前目标。]

## 问题或任务
[明确要 AI 做什么，只写一个主要任务。]
[例如：分析失败原因 / 解释代码流程 / 生成测试点 / 审查潜在问题]

## 上下文
### 1. 现象 / 输入
[描述现象、输入数据、需求说明、日志摘要等。]

### 2. 相关代码 / SQL / 配置
```text
[粘贴相关代码、SQL、配置或接口说明]
```

### 3. 复现步骤 / 调用方式
1. [步骤 1]
2. [步骤 2]
3. [步骤 3]

### 4. 期望结果
[正常情况下应该是什么结果]

### 5. 实际结果
[实际发生了什么]

### 6. 最近变更 / 已知限制
- [最近改动 1]
- [限制 1]

## 约束
- [例如：不要直接修改代码]
- [例如：保持现有接口不变]
- [例如：优先按概率排序]
- [例如：如果信息不足，请明确指出缺什么]

## 希望输出
- [输出项 1]
- [输出项 2]
- [输出项 3]

## 输出格式
[明确要求结果长什么样。]
[例如：Markdown 表格 / 按高中低排序 / JSON / 分步骤列表]
```

---

## 开发中心常用填法示例

### 1. Bug 分析

```markdown
# 任务名称
Bug 分析

## 角色
请以后端开发人员的视角处理这个任务。

## 背景
订单提交接口偶发失败。

## 问题或任务
分析 Bug 的可能原因，并给出验证方法。

## 上下文
### 1. 现象 / 输入
用户点击提交订单后，页面一直转圈，偶发提示库存不足。

### 2. 相关代码 / SQL / 配置
```python
# 粘贴 submit_order 相关代码
```

### 3. 复现步骤 / 调用方式
1. 购物车加入两个商品
2. 其中一个商品叠加优惠券
3. 点击提交订单

### 4. 期望结果
订单成功创建。

### 5. 实际结果
接口失败，部分请求超时。

## 约束
- 不要直接修改代码
- 按概率从高到低排序

## 希望输出
- 可能原因
- 每个原因的验证方法
- 建议排查顺序

## 输出格式
用分点列表输出。
```

### 2. 代码 Review

```markdown
# 任务名称
代码 Review

## 角色
请以代码 Reviewer 的视角处理这个任务。

## 问题或任务
请审查这段代码的正确性、边界条件、异常处理和测试覆盖。

## 相关代码 / SQL / 配置
```python
# 粘贴需要 Review 的代码
```

## 约束
- 只指出问题，不直接重写代码
- 按严重程度排序

## 希望输出
- 高风险问题
- 中风险问题
- 低风险问题
- 缺失的测试方向
```

### 3. 测试点生成

```markdown
# 任务名称
测试点生成

## 角色
请以测试负责人的视角处理这个任务。

## 问题或任务
请根据需求生成测试点。

## 上下文
### 1. 现象 / 输入
功能：后台登录
字段：用户名、密码、验证码
规则：密码连续输错 5 次后锁定 10 分钟

## 约束
- 按正常场景、异常场景、安全场景分类
- 每条测试点要有预期结果

## 输出格式
用 Markdown 表格输出：分类 | 测试点 | 预期结果
```

---

## 使用建议

- 一次只让 AI 完成一个主要任务。
- 如果信息不足，优先补上下文，不要只反复追问“再详细一点”。
- 模板可以删减，但不要把“背景、任务、约束、输出格式”都删掉。
- 团队共享时，建议每个模板都附一个真实示例。
