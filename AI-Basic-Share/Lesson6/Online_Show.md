# Online_Show

## 业务背景

本文件用于课堂现场演示：**用 Copilot 把一个 Excel 设计书转换成 Markdown 文档工具**。

本课主题是 **用 AI 制作小工具**，重点演示：
- 如何用需求模板把模糊想法变成可执行的输入
- 如何让 Copilot 先提问、把需求理顺，再动手
- 如何通过样例验证和迭代让工具可用
- 如何处理真实场景中的复杂需求（多 Sheet、图片、路径）

> 课堂核心思路：**先让 AI 把需求问清楚，再让它动手。需求越清楚，工具越接近可运行。**

---

## 演示目标

现场做一个命令行小工具：读取一个 **Excel 设计书**（多 Sheet、含图片），输出一份 **Markdown 文档**。

关键需求点（也是本演示的难点）：
- Excel 不是纯数据表，而是**设计书**，有多个 Sheet。
- 很多 Sheet 里还**嵌有图片**。
- 图片要**独立于 Markdown 文件存在**（导出到单独文件夹）。
- Markdown 里用**图片地址**引用这些图片，而不是把图片内嵌进 Markdown。

| 步骤 | 内容 | 时间 |
|------|------|------|
| 1 | 用需求模板描述目标 | 2 分钟 |

## 步骤 1：用需求模板描述目标

### 讲解目标
让学员看到：把模糊想法填进需求模板，是让 AI 稳定输出的第一步。

### 现场演示 Prompt（第一次提示词）

> 请把下面这段需求复制给 Copilot。

```
请帮我用 Python 做一个命令行小工具，把一个 Excel 设计书转换成 Markdown 文档。

## 目标

我要做一个工具，用来把 Excel 设计书转换成 Markdown 文档，方便在文档平台或 Git 上查看和评审。

## 范围

- 本工具要做：读取 Excel 设计书，按 Sheet 生成对应的 Markdown 章节。
- 本工具不做：不修改原 Excel 文件，不做复杂的格式美化。

## 输入

- 输入来源与格式：一个 .xlsx 文件，作为设计书使用，不是纯数据表。
- 结构说明：文件有多个 Sheet，每个 Sheet 代表设计书的一个章节。
- 图片说明：很多 Sheet 中嵌有图片，图片需要独立于 Markdown 文件存在。
- 样例数据：我会在后续提供一份样例 Excel。

## 输出

- 输出格式与保存位置：生成一个 .md 文件，放在与输入同目录下。
- 图片处理：把 Excel 中的图片导出到一个独立的 images 文件夹。
- 图片引用：Markdown 中用相对路径记录图片地址，例如 ![图片](images/xxx.png)，不要把图片内嵌进 Markdown。
- 章节结构：每个 Sheet 对应 Markdown 中的一个二级标题（##）。

## 规则

- 规则 1（正常流程）：按 Sheet 顺序生成章节，表格内容转成 Markdown 表格。
- 规则 2（边界条件）：Sheet 中没有图片时，不生成空的图片引用。
- 规则 3（异常数据处理）：单元格为空时保留空位，不报错。

## 异常与提示

- 文件不存在时：提示文件路径错误。
- 文件不是 .xlsx 时：提示格式不支持。
- 图片无法导出时：在 Markdown 中标注图片缺失，不中断整个转换。

## 技术要求

- 使用语言与版本：Python 3。
- 依赖库限制：可以使用 openpyxl 等第三方库。
- 运行方式：命令行，例如 python excel_to_md.py 输入.xlsx。
- 是否需要图形界面：不需要。

## 验收标准

- 验收点 1（可执行）：能对样例 Excel 正常运行。
- 验收点 2（结果正确）：每个 Sheet 生成对应章节，图片地址正确。
- 验收点 3（异常可提示）：文件不存在、格式错误时有明确提示。

## 交付物

- 脚本文件：excel_to_md.py。
- 使用说明：README 或命令行帮助。
- 样例输入输出：一份样例 Excel 和对应的 Markdown 输出。

---

你先不要开始动手做，当你认为你已经对我的需求理解超过 95% 以上的时候，再动手。接下来你有什么问题，一个一个问我。
```

### 讲解要点
- 第一次提示词就要求 Copilot **先提问、后动手**，避免它按自己的假设乱做。
- 重点强调“图片独立存放 + Markdown 记录地址”，这是本工具区别于普通表格转换的核心。
- 让学员看到：需求模板里的每一项，最后都会变成工具的一个功能点。

---

## 步骤 2：让 Copilot 提问，把需求理顺

### 讲解目标
让学员看到 Copilot 会围绕哪些点提问，以及我们如何回答，把需求补全。

### 常见提问与建议回答

| Copilot 可能问的问题 | 建议回答 |
|------|----------|
| 图片导出到什么文件夹？ | 输出目录下的 images 文件夹 |
| 图片在 Sheet 中的位置怎么处理？ | 按图片在 Sheet 中的大致位置顺序记录 |
| 表格转 Markdown 时，合并单元格怎么处理？ | 合并单元格按左上角值填充 |
| 输出文件名怎么定？ | 与输入文件名相同，扩展名改为 .md |
| 是否需要保留 Sheet 顺序？ | 需要，按 Excel 中的 Sheet 顺序 |
| 图片命名规则？ | 用 Sheet 名 + 序号，例如 sheet1_1.png |

### 讲解要点
- 提问不是浪费时间，而是把“AI 的假设”变成“你的明确要求”。
- 回答问题时，尽量给出**具体、可执行**的答案，而不是“你看着办”。
- 这一步做完，需求就从 70% 清晰提升到 95% 以上。

---

## 步骤 3：让 Copilot 生成最小可用版本

### 讲解目标
让 Copilot 先给出实现思路和文件结构，再生成代码，避免一次写太多。

### 现场演示 Prompt

```
好的，需求已经清楚了。请先不要直接写完整代码。

请先给出：
1. 实现思路（分几步）
2. 文件结构（需要哪些文件）
3. 关键函数清单（每个函数做什么）

确认结构没问题后，再开始生成 excel_to_md.py 的代码。
```

### 讲解要点
- 复杂工具不要一次生成完整代码，先对齐结构。
- 让 Copilot 先给“思路 + 函数清单”，我们确认后再写代码。
- 这一步能显著减少返工。

---

## 步骤 4：跑样例、故意触发错误、迭代

### 讲解目标
让学员看到“运行 → 报错 → 反馈 → 迭代”的真实循环。

### 4.1 准备样例
准备一份小的样例 Excel（2 个 Sheet，其中一个含 1 张图片），先跑通最小流程。

### 4.2 故意触发一个错误
故意输入一个不存在的文件路径，观察工具是否给出友好提示。

### 4.3 现场演示 Prompt（把报错反馈给 Copilot）

```
我运行了脚本，遇到以下报错：

[把终端里的报错信息粘贴到这里]

请帮我分析原因，并给出修复后的代码。
```

### 讲解要点
- 报错信息要**原样粘贴**，不要自己转述，AI 才能准确定位。
- 每修一个错，就重新跑一次样例验证。
- 迭代不是无限循环，达到验收标准就停。

---

## 步骤 5：对照验收标准收尾

### 讲解目标
让学员用验收清单判断工具是否真的完成。

### 现场演示 Prompt

```
请对照以下验收标准，检查当前工具是否满足，并列出还缺什么：

- 能对样例 Excel 正常运行
- 每个 Sheet 生成对应章节
- 图片导出到独立文件夹，Markdown 用相对地址引用
- 文件不存在、格式错误时有明确提示
- 有最小使用说明
```

### 讲解要点
- 工具不是生成出来就完成，能运行、能验证、别人能用才算完成。
- 使用说明不要省略，这是团队复用的基础。

---

## 课堂小结

本次演示完整走了一遍“用 AI 制作小工具”的流程：
1. 用需求模板描述目标
2. 让 Copilot 先提问、把需求理顺
3. 先对齐结构，再生成最小可用版本
4. 跑样例、报错、迭代
5. 对照验收标准收尾

> 关键一句话：**先让 AI 把需求问清楚，再让它动手。**
